# Практика: заявка с сохранением состояния

Работаем с одной формой на протяжении всего занятия. После каждого задания проверяйте результат в браузере.

## Блок 1. Форма и событие `submit` — 10 минут

**Теория:** слайды 1.1–1.4.  
**Цель:** перехватить отправку формы и оставить пользователя на текущей странице.

### 1.1 — Проверьте связи формы

Откройте `index.html` и найдите форму `.application-form`.

Убедитесь, что:

- все три поля находятся внутри одного `form`;
- `for` каждой подписи совпадает с `id` ее поля;
- поля имеют `name="name"`, `name="email"` и `name="topic"`;
- основная кнопка имеет `type="submit"`;
- кнопка очистки имеет `type="button"`.

Изменять готовые связи не нужно. Это карта данных, с которой будет работать JavaScript.

### 1.2 — Подпишитесь на отправку формы

В `script.js` найдите блок 1.2. Сейчас обработчик подписан на событие `click`.

Замените его на событие `submit`. Отправьте форму кнопкой, затем нажатием Enter в поле имени. В обоих случаях в Console должно появиться:

```text
1.2. Получено событие submit
```

### 1.3 — Остановите перезагрузку

Первой строкой обработчика вызовите у объекта события метод `preventDefault()`.

Затем измените текст элемента `result`:

```text
Форма обработана без перезагрузки
```

**Видимый результат:** адресная строка не меняется, страница не перезагружается, сообщение появляется в правой колонке.

### Быстрая проверка блока 1

- кнопка и Enter запускают один обработчик;
- страница не перезагружается;
- в Console нет красных ошибок;
- на странице видно новое сообщение.

## Блок 2. Встроенная HTML-валидация — 10 минут

**Теория:** слайды 2.1–2.4.  
**Цель:** передать браузеру простые правила корректного ввода.

### 2.1 — Сделайте значения обязательными

В `index.html` добавьте атрибут `required`:

- полю имени;
- полю email;
- списку выбора темы.

Попробуйте отправить пустую форму. Браузер должен остановиться на первом незаполненном поле, а обработчик `submit` не должен вывести новое сообщение.

### 2.2 — Уточните правила имени и email

- Полю имени добавьте `minlength="2"`.
- У поля email замените `type="text"` на `type="email"`.

Не добавляйте регулярные выражения или собственные сообщения об ошибках: в этом блоке используется только встроенная проверка браузера.

### 2.3 — Пройдите три контрольных сценария

Последовательно проверьте:

1. пустую форму;
2. имя из одного символа и email без `@`;
3. имя из двух или более символов, корректный email и выбранную тему.

**Видимый результат:** только третий сценарий доходит до обработчика и показывает сообщение блока 1.

### Быстрая проверка блока 2

- пустые поля не проходят проверку;
- имя из одного символа не проходит проверку;
- строка `student` не проходит как email;
- корректная форма вызывает `submit`;
- `preventDefault()` не отключает HTML-валидацию.

## Блок 3. `FormData` и результат на странице — 10 минут

**Теория:** слайды 3.1–3.4.  
**Цель:** получить значения по их `name` и показать их пользователю.

Все действия выполняются **внутри** обработчика `submit`, после `preventDefault()`.

### 3.1 — Создайте `FormData`

В блоке 3.1 создайте объект данных текущей формы:

```js
const formData = new FormData(form)
```

Он должен создаваться при каждой корректной отправке, а не один раз при загрузке страницы.

### 3.2 — Получите три значения

Через метод `get` создайте три константы:

- `name` из значения с именем `name`;
- `email` из значения с именем `email`;
- `topic` из значения с именем `topic`.

Выведите их в Console с понятными подписями. Если вместо значения появился `null`, сравните строку в `get(...)` с атрибутом `name` в HTML.

### 3.3 — Покажите подтверждение

Замените временный текст блока 1 на сообщение через шаблонную строку:

```text
Анна, заявка на тему «Городская мастерская» принята. Подтверждение: anna@example.com
```

Используйте `textContent` и переменные из задания 3.2. Не вставляйте готовые имя, тему или email прямо в строку.

**Видимый результат:** при новых значениях формы меняется и подтверждение справа.

### Быстрая проверка блока 3

- `FormData` создается внутри обработчика;
- все три `get` возвращают введенные значения;
- Console показывает те же данные, что и страница;
- повторная отправка обновляет результат без перезагрузки.

## Блок 4. Объект, JSON и `localStorage` — 10 минут

**Теория:** слайды 4.1–4.4.  
**Цель:** сохранить один снимок формы под постоянным ключом.

Продолжайте работу внутри обработчика `submit` после получения значений.

### 4.1 — Соберите объект заявки

В блоке 4.1 создайте объект `application` с тремя свойствами:

```js
const application = {
  name,
  email,
  topic,
}
```

Выведите объект в Console и раскройте его стрелкой.

### 4.2 — Получите JSON-строку

Создайте `applicationJson` с помощью `JSON.stringify(application)`.

Выведите рядом объект и JSON-строку. Объясните соседу одним предложением, чем они визуально отличаются в Console.

### 4.3 — Сохраните черновик

Сохраните строку в `localStorage` под готовой константой `STORAGE_KEY`.

После сохранения измените `localStorageStatus.textContent` на:

```text
Черновик сохранен
```

Откройте DevTools → Application → Local Storage и найдите ключ `drip-lesson-1-5-application`. Измените тему и отправьте форму снова: значение под тем же ключом должно обновиться.

**Видимый результат:** зеленая отметка на странице и JSON-строка в Application.

### Быстрая проверка блока 4

- объект содержит актуальные `name`, `email`, `topic`;
- `JSON.stringify` возвращает строку;
- `setItem` использует постоянный ключ;
- повторная отправка заменяет значение;
- после обычной перезагрузки ключ остается.

## Блок 5. Восстановление, очистка и `sessionStorage` — 10 минут

**Теория:** слайды 5.1–5.4.  
**Цель:** пройти обратный путь от JSON-строки к заполненной форме.

### 5.1 — Восстановите сохраненные значения

Вне обработчика `submit`, в блоке 5.1:

1. получите строку через `localStorage.getItem(STORAGE_KEY)`;
2. проверьте ее существование через `if`;
3. внутри `if` вызовите `JSON.parse`;
4. присвойте сохраненные значения свойствам `.value` элементов `nameInput`, `emailInput` и `topicSelect`;
5. покажите в `result` сообщение `Черновик восстановлен`;
6. покажите в `localStorageStatus` сообщение `Найден сохраненный черновик`.

Сначала сохраните заявку из блока 4, затем перезагрузите страницу.

**Видимый результат:** три поля автоматически заполняются прежними значениями.

### 5.2 — Подключите кнопку очистки

В готовом обработчике `clearButton`:

- удалите запись через `localStorage.removeItem(STORAGE_KEY)`;
- вызовите `form.reset()`;
- измените `result.textContent` на `Черновик удален`;
- измените `localStorageStatus.textContent` на `Локального черновика нет`.

После очистки перезагрузите страницу: удаленные значения не должны вернуться.

### 5.3 — Создайте временную копию

Внутри обработчика `submit`, рядом с записью в `localStorage`:

- сохраните тот же `applicationJson` в `sessionStorage` под тем же ключом;
- измените `sessionStorageStatus.textContent` на `Копия существует до закрытия вкладки`.

В обработчик очистки добавьте `sessionStorage.removeItem(STORAGE_KEY)` и верните текст `Сессионной копии нет`.

Найдите обе записи во вкладке Application и ответьте:

1. что сохранится после перезагрузки страницы;
2. что исчезнет после закрытия вкладки;
3. какое хранилище подходит для долговременного черновика.

### Быстрая проверка блока 5

- при отсутствии ключа `JSON.parse` не вызывается;
- после перезагрузки поля восстанавливаются из `localStorage`;
- кнопка очищает форму и обе записи;
- `localStorage` и `sessionStorage` используют одинаковые методы;
- вы можете объяснить разницу во времени жизни данных.

## Готово: что показать преподавателю

1. Откройте Console и убедитесь, что красных ошибок нет.
2. Покажите встроенную ошибку браузера на некорректном email.
3. Отправьте корректную заявку и покажите подтверждение.
4. Найдите JSON в Application.
5. Перезагрузите страницу и покажите восстановленные поля.
6. Нажмите «Удалить черновик» и перезагрузите страницу еще раз.
7. Выполните `git push` и приложите ссылку на репозиторий.

## Если основная часть готова раньше

Не начинайте новую большую функцию. Добавьте одно небольшое улучшение:

- после восстановления выводите имя участника в сообщении;
- меняйте текст статуса на `Черновик обновлен` при повторной отправке;
- добавьте необязательное поле комментария и включите его в объект заявки.

Дополнительная часть не обязательна и проверяется только после основной.
